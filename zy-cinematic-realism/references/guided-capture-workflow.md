# 按需引导的摄影创作

本流程吸收 Jury《双入口使用手册 v2.5.3》的方案审阅、修改与结构化交付方法。摄影选择仍由[Capture Design](capture-design.md)管理，最终表达沿用[Prompt Compiler](prompt-compiler.md)。

## 触发与交付阶段

| 当前请求 | 本轮交付 |
| --- | --- |
| 先做 Plan、先看方案、确认后再写、按 Jury 手册完整流程 | 需求与授权参考分析，形成可审阅 Plan，等待修改或确认 |
| 直接出词、只给提示词、器材你选 | 补齐必要 OPEN 选择，直接编译普通文本 |
| 直接输出 JSON、按 Jury JSON Brief 输出 | 依用户指定格式直接编译；用户同时要求先审方案时，先交付 Plan |
| 只分析、只查资料、只检查 | 停在所请求的分析、检索或检查 |
| 对已接受方案换模型或换格式 | 继承当前有效值与范围，执行现有转码流程 |

依据当前请求选择交付阶段。后续明确要求跳过等待时即可编译。只点名 JSON 格式时执行格式请求；“按手册完整流程”或“先审方案”才触发等待。普通 Create 沿用快速路径，专业程度与流程深度由对话自然体现。

## 需求与参考

先恢复当前 Scene Master，识别画面目标、已指定事实、媒介、参考职责和当前任务范围。实际图片按[参考职责](reference-role-router.md)、[媒介路由](medium-router.md)及[Dream Decode](dream-decode.md)处理。文字 Decode Card 可直接作为已提供资料使用，观察结论保持其原有证据范围。

参考分析说明可见区域、具体色相与明暗关系、可辨材质和清晰层次。只有实际使用采样或测量工具后才报告相应测量值。光色参考的授权止于光色，人物、衣服、道具和故事事实继续取自当前场景。摄影器材的历史身份需要制作来源。

器材选型按当前目标查[器材库](equipment-library.md)，电影事实查[电影与场景方法库](cinema-shot-library.md)，术语消歧查[53 词索引](camera-language-dictionary.md)。读到足够依据即可继续，研究说明与待核验项可简短附在方案相关选择旁。

## Capture Plan 的可审阅内容

从同一 Scene Master 展示当前候选，按任务裁剪以下内容。

- 画面目标、主体当前动作、媒介与画幅，以及必须保留的事实。
- 构图与空间，包含主体大小、机位高度和朝向、必要距离、遮挡及前后层次。
- 成像与清晰关系，包含所选器材及用途、焦距与有效画幅、对焦目标和必须可读的平面。非摄影媒介说明对应的视点与制作逻辑。
- 现有光源、曝光与色彩关系、关键表面，以及必要效果的条件和范围。
- 等待确认的可见选择，以及用户已要求的下一步输出格式。存在真正阻塞的冲突时，指出最小决策。

方案长度随请求调整。用户只要简短方案时，可用几句或短表呈现这些关键关系。模型未知而本阶段能使用共享摄影设计时，先提供模型中立 Plan。计划中的数值使用明确基准，未披露的内部值继续保留其实际状态。

## 修改、接受与继续

Plan 读取现有记录的“决策来源、锁定状态、接受状态、适用范围”。候选和修改候选对应 proposed / revised，明确采纳的选择按范围记录 accepted；用户接受范围与最初决策来源分别保留。编译完成只记录已交付相应文本，生成、检视和评价状态由各自实际事件确定。

“接受这份方案”保护其中已展示、可识别的具体选择。明确采纳的器材、视点、配色或清晰关系在该范围成为 USER-LOCKED，未展示的内部参数继续按原有 OPEN 或锁定状态处理。“这张图不错”沿用其实际认可的外观范围。

修改以最新有效候选或已接受方案为基础，累计保留先前指令。用户只改背景虚化时，更新清晰关系及必要的 OPEN 依赖，保留人物、机位、光源、颜色与其余有效选择。相关值全部锁定且冲突时，按现有最小问题策略处理。

用户只要求修改 Plan 时，展示修改后的方案并继续等待。用户要求“改好直接出词／JSON”时，完成修改后立即编译。“接受方案，但改某项”接受其余可见选择，该修改项按本次授权更新；具体依赖仍按锁定范围判断。

“继续”可在只有一份清楚的当前方案、且下一步交付已明确时推进该步骤。存在多个未选方案或下一步格式未定时，简短确认实际缺少的选择。已经接受的同一方案可直接编译所请求格式。

## 编译出口

普通文本由现有模型适配器编译。用户提供 JSON schema 时沿用其原层级、字段与类型。明确选择 Jury JSON Brief 时按[已核对的静帧格式](jury-json-brief.md)编译。格式转换携带当前 OPEN 候选和 USER-LOCKED 值，当前未指定的事实按所选格式表达。

研究链接、评分、测试记录、状态元数据留在方案或交接记录中。最终对象使用所选 schema 的字段，参考职责和保留／修改关系映射到相关画面字段。任何固定颜色数量仅作用于用户选择的格式。源结构不可读或内层结构缺失时，说明具体缺口并请求该结构或允许使用已核对格式。

独立新项目从新输入建立状态。同系列通过现有[连续性](continuity-cards.md)继承项目共同选择，每镜局部值按其范围延续；新参考依职责重判。用户需要跨对话延续时使用现有[项目交接](project-handoff.md)，保留当前方案、接受范围、待决项及已交付内容。

# Seedream 5.5 Adapter

## 身份与依据

- 模型名称为 Seedream 5.5。
- 可识别明确含有 5.5 版本信息的中英文写法。依照[模型路由](../model-routing.md)，新建且未约定版本的 Seedream 请求默认使用 5.5。“即梦”需在上下文中确实指向 Seedream 提示词，具体前端开放的版本和功能另行依据实际界面判断。
- 核实日期为 2026-11-17。官方发布文章日期为 2026-11-09，火山方舟教程更新日期为 2026-11-13。
- Seedream 5.0 Pro 使用其独立适配器。未确定版本的 Seedream 或后续新版本，先按已知上下文及可核实信息处理。

官方资料支持文生图、单图编辑与多参考图生成，示例使用自然语言描述场景、空间、光线、材料和编辑保留关系。官方同时提供原生 RGBA 透明图、图层拆分及富文本 OCR 能力说明。具体操作依赖用户当前前端或工具实际开放的功能。[模型页](https://seed.bytedance.com/en/seedream5_5) · [发布文章](https://seed.bytedance.com/en/blog/more-realistic-images-more-stable-editing-across-100-rounds-introducing-seedream-5-5/) · [火山方舟教程](https://console.volcengine.com/ark/region%3Acn-beijing/docs/seedream-5-5)

## 编译方式

把当前 Scene Master 编译成自然语言的制作要求。按画面关系组织信息，优先明确主体、动作、位置、尺度、前中后景、遮挡、视觉中心及光源。细节密度由任务复杂度决定，保留能改变画面结果的信息。

可采用以下内容顺序，根据任务合并或省略段落。

1. 成图目的、交付画幅与用户固定事实。
2. 当前动作、人物关系、主体与物件的位置。
3. 机位、观看距离、景别、构图与必须清楚的平面。
4. 现有光源、明暗关系、色彩和材料响应。
5. 必要的器材、光学特征、成像介质及可见结果。
6. 参考职责、精确可见文字，以及针对当前问题的保留与修改要求。

默认使用普通文本。用户明确请求 JSON 时，按其结构导出同一 Scene Master。

## 摄影设计

沿用[摄影设计](../capture-design.md)中已经确定的选择。型号、实际焦距、光圈、有效画幅、机位与景深保持其各自含义。用户锁定了器材时保留器材，并用自然语言补充可观察的成像结果。

以树林旋焦为例，表达眼睛清晰、人物与背景树叶分离、外围失焦叶片轻微环绕中心，同时保持人物轮廓和树干几何自然。需要时附上 `swirly bokeh` 等准确短语，控制效果作用的区域和强度。旋焦、眩光、卤光、滤镜扩散及天气散射各自遵循现有条件和授权范围。

机身与镜头名称作为摄影信息保留。色彩、反差、颗粒、光线和空间关系仍需写出画面目标。资料核验说明、选择理由与内部锁定状态按用户需要另行提供。

## 参考图与 Dream Decode

为每张输入图指定明确职责，例如底图、身份、服装、场景拓扑、物件、材料、构图或授权风格。说明各职责作用的区域和边界，解决参考之间的冲突。多参考合成时写清新位置、尺度、遮挡、接触和光线整合要求。

Dream Decode 继续使用共享 Scene Master 与 Decoded Visual Grammar。保留已授权的 Primary Medium、身份关键的 Medium Constraints、实际观察到的 Expression Mechanism、当前选用的三至五条 Active Core Rules 与 Transfer Scope。OPEN 摄影选择依据有效的 Hybrid Decisions 解决。用户指定事实与参考职责保持优先级。

非摄影参考按其媒介编译，明确绘画、纸张、笔触、边缘或其他对应的成像逻辑。Do Not Transfer 内容继续留在迁移范围之外。参考职责可直接用自然语言说明，无需为每次生成增加独立的结构化报告。

## 编辑与连续修改

使用用户本轮指定的图或最近实际待修改图作为编辑底图，包括首张失败结果。结合当前有效 Scene Master，说明本轮修改以及需要保留的身份、布局、物件、光线和先前已接受特征。尚未认可的图像保留其实际状态。纯文字修订沿用当前有效场景及候选摄影值，多轮修改累计更新状态。

局部编辑尽量定位到可识别对象、区域及关系。前端提供蒙版、区域选择或标注时，使用实际可用的控制并与文本对应。依靠普通图像输入时，用清楚的空间描述表达编辑范围。

保持人物、物件或布局的要求按当前任务明确表达。成图后的保留程度需依据实际图像检查，官方的连续编辑宣传数据只作为能力背景。

修复局部问题时保留已经成立的画面关系。修复结构性问题时回到 Scene Master，重新说明相关空间、机位或清晰关系。用户要求换设备、改焦段或调景深时，同步更新其关联的 OPEN 决策。

## 透明图、图层与文字

用户请求透明背景或半透明素材时，可描述主体边缘、透明区域和所需保留的半透明材料，并使用前端实际提供的透明输出功能。图层拆分、富文本识别和其他接口能力同样在用户提出相应任务且当前工具支持时使用。

需要生成可见文字时，给出准确文案、语言、位置、方向、层级与排版关系。需要识别现有文字时，区分转录任务与重新生成文字的任务。密集信息布局依据用户要求组织，摄影叙事场景保留其视觉主次。

## 参数与输出

在文本中写明期望画幅与对应构图。尺寸、分辨率、种子、参考图数量、输出格式和 API 字段依据已核实的具体前端设置处理。普通提示词只包含生成需要的信息，接口调用数据采用对应工具的真实结构。

使用目标模型的自然语言表达，不导入其他模型的命令参数。当前工具未开放的能力可作为需求描述保留，并清楚说明交付范围。模型转换保留摄影选择、场景事实、参考职责和媒介身份。
